# Импорт/экспорт товаров: решения

Приложение реализует [исходное техническое задание](original-task.md). Локальная среда запуска — Docker Compose. Экспорт XLSX сохраняет данные модели для повторного импорта.

## Обязательные требования

Slim + Doctrine ORM, Angular TypeScript strict, реляционная БД, Symfony Messenger + RabbitMQ/Kafka; страницы входа, импорта, списка и карточки; upsert по уникальному external_code; отдельные services/repositories/controllers; атомарная запись товара, атрибутов и изображений; ошибки строк не прекращают импорт; статус и отчёт задания; серверная пагинация и фильтры name/min_price/max_price; NgRx Actions/Effects/Selectors и async pipe; UI-kit; authentication, guard/interceptor/lazy routes; Docker multi-stage, fixtures, CRUD/e2e, PHPStan ≥5, CS Fixer, CI, OpenAPI, README, .env.example.

Дополнительные требования: обратный XLSX-импорт экспортированного каталога, сохранение закупочной цены и точное восстановление исходных фото-колонок в XLSX-экспорте, показ/скрытие пароля, увеличение фотографии, коричневая тема с оранжевыми акцентами и поиск по отдельным словам без учёта регистра.

## Проверенный Excel

Один лист «Лист1», A1:AX41, 50 заголовков, 40 товаров, 19 колонок «Доп. поле: …». Ключ — «Внешний код» (не UUID, Код или Наименование). Цены — строки с десятичной запятой. Изображения берутся из «Доп. поле: Ссылка на упаковку» и «Доп. поле: Ссылки на фото»: 131 ссылка, 28 уникальных, http://catalog.collant.ru. Значения дополнительных полей хранятся как текст; пустые значения не создают атрибут. Нулевые значения сохраняются. Ссылки с подозрительными опечатками не исправляются.

## Принятые решения

- PHP 8.4, Slim 4, Doctrine ORM 3, Messenger 7.4 / EventDispatcher 8.1, PostgreSQL 16, RabbitMQ 4.3.6, Angular 21 + NgRx 21, Bootstrap 5, Node 22 (совместимый Angular диапазон); точные зависимости фиксируются lock-файлами.
- Одна origin через nginx: cookie HttpOnly, SameSite=Lax, CSRF для изменений; Secure в HTTPS. Пароль задаётся окружением, хранится в БД в виде хеша; нет регистрации и дополнительных ролей.
- Цена DECIMAL(14,2), закупочная цена хранится отдельным DECIMAL(14,2) ради без потерь экспорт/импорт. Скидка DECIMAL(16,4), рассчитывается как (price − purchase_price) / price × 100 с усечением до четырёх знаков. Продажная цена >0, закупочная ≥0; закупочная больше продажной допускается (отрицательная скидка отражает формулу ТЗ).
- Обязательны Внешний код, Наименование, Цена: Цена продажи, Закупочная цена. Описание опционально. Неописанные ТЗ обычные колонки игнорируются; экспорт сохраняет модель задания, а не все 50 исходных колонок.
- Читается единственный непустой лист. Несколько непустых листов отвергаются как неоднозначная структура. Заголовки сопоставляются по названиям после trim. Формулы в импортируемых данных запрещены, текстовые идентификаторы и числовые маски с ведущими нулями сохраняются.
- Дубликаты внутри файла: последняя успешная строка обновляет товар. Повторная доставка задания не начинает завершённую задачу заново; прогресс и отчёт сохраняются вместе с результатом строки. Worker сериализует импорты, блокировка задания защищает от конкурирующих consumers.
- Полная замена атрибутов/изображений при успешной строке. Пустое доп. поле удаляет старое значение. Любая ошибка изображения пропускает всю строку и сохраняет старый товар; никаких частично обновлённых связей. Общий импорт продолжает работу.
- Изображения скачиваются только с публичных HTTP(S)-адресов, DNS закрепляется на проверенном IP; redirects/proxy запрещены, ограничены время/размер/разрешение, MIME проверяется по содержимому. Имена случайные/хешированные, файловые операции компенсируются при откате.
- Экспорт: Внешний код, Наименование, Описание, Цена: Цена продажи, Закупочная цена, Скидка, затем сортированные Доп. поле: …, включая оригинальные фото URL. Строковые ячейки явно строковые (без formula injection), цены числовые. URL дополнительно хранятся в атрибутах, поэтому точное содержимое исходных фото-колонок восстанавливается.
- Лимиты: файл 10 MiB, распакованное содержимое 50 MiB, XML 20 MiB, 10 000 строк, 200 колонок, 100 000 фактических ячеек, 1 000 000 XML nodes/attributes, 4 096 styles, 100 000 shared strings/rich runs. Для обратного импорта экспортов каталог ограничен 194 ключами, 100 000 прямоугольными ячейками экспорта и 2 MiB текстового бюджета с резервом. 10 изображений на товар, 5 MiB/изображение, общий сетевой срок 10 секунд/URL, 25 MP. Endpoint импорта ограничен по пользователю.
- Frontend OnPush, отслеживание строк по id, debounce/distinctUntilChanged фильтров, switchMap для отмены устаревших запросов; polling завершается на конечном статусе и при уничтожении компонента.

## Контракт API

Все ответы JSON, исключение XLSX и изображения. Ошибка: `{error:{code:string,message:string,details?:unknown}}`.
Session: `GET /api/auth/session` → `{authenticated:boolean,username?:string,csrf_token:string}`; `POST /api/auth/login` body `{username,password}` → session; `POST /api/auth/logout`.
Product: `{id:number,external_code:string,name:string,description:string,price:string,purchase_price:string,discount:string,attributes:ProductAttribute[],images:ProductImage[]}`; attribute `{id:number,key:string,value:string}`; image `{id:number,url:string,path:string}` (path is authenticated `/api/images/<safe filename>`).
`GET /api/products?page=1&limit=20&name=&min_price=&max_price=` → `{items:Product[],page:number,limit:number,total:number,total_pages:number}`.
`GET /api/products/{id}` → Product. `GET /api/products/export` → XLSX всех товаров (не текущей страницы).
`POST /api/imports` multipart `file` → 202 `{id:string,status:"queued"}`.
`GET /api/imports/{id}` → `{id,status:"queued"|"processing"|"completed"|"failed",total,processed,created,updated,skipped,errors:[{sheet,row,message}],message?:string}`.
`GET /api/health` → health status. Все изменения, включая login, требуют `X-CSRF-Token`; same-origin only.
