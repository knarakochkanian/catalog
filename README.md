# Импорт / экспорт товаров

Приложение для импорта и экспорта товаров из Excel: PHP Slim + Doctrine ORM, Angular + NgRx, PostgreSQL, Symfony Messenger + RabbitMQ. Страницы входа, импорта, каталога и карточки работают с API. Экспорт XLSX предназначен для повторного импорта. Локальный запуск — через Docker Compose.

Интерфейс использует коричневую палитру с оранжевыми акцентами. На странице входа пароль можно показать и скрыть; исходное значение сохраняется, по умолчанию поле скрыто. Фотография в карточке открывается в увеличенном виде. Закрытие — кнопка, Esc или фон; фокус возвращается на выбранную фотографию.

## Быстрый запуск в Docker

Нужны работающий Docker Desktop/Engine, Docker Compose v2 и Make.

```sh
make setup
# Откройте .env; ADMIN_USERNAME и ADMIN_PASSWORD — данные входа.
# setup генерирует случайные пароли и не выводит их в журнал.
make up
```

Приложение: **http://localhost:8080**. Первая сборка скачивает зависимости. Готовность: `curl http://localhost:8080/api/health` → `{"status":"ok"}`. Учётная запись создаётся миграцией; пароль должен содержать минимум 12 символов. Изменение ADMIN_PASSWORD после создания пользователя не меняет уже сохранённый хеш.

```sh
make migrate       # Повторный запуск миграций безопасен
make fixtures      # Явное добавление демонстрационного товара/атрибутов/изображения
make logs
make down          # Останавливает сервисы, сохраняет данные в volumes
```

Не используйте `docker compose down -v`, если нужно сохранить импортированные данные.

## Стек и структура

- PHP 8.4, Slim 4.15.3, Doctrine ORM 3.7.4 / DBAL 4.5.0, Messenger 7.4.20, PhpSpreadsheet 5.10.0.
- Angular 21.2, NgRx 21, TypeScript 5.9, RxJS 7.8, Bootstrap 5.3; Node 22.21. Точные версии: `frontend/package-lock.json`.
- PostgreSQL 16; RabbitMQ 4.3.6; nginx; PHP AMQP 2.2.0.
- `backend/src/Http` — небольшие контроллеры, сессия/CSRF, валидация HTTP.
- `backend/src/Import` — проверка архива, чтение Excel, нормализация цен, безопасное скачивание.
- `backend/src/Service` — импорт строки и экспорт; `Repository` — запросы; `Entity` — Doctrine-модель.
- `backend/bin` — миграции, fixtures, consumer и публикация сохранённых заданий.
- `frontend/src/app` — отдельные модели/API-сервисы, lazy страницы, guard/interceptor, NgRx списка.
- `tests` — браузерный e2e и HTTP smoke; `backend/tests` — бизнес-логика/CRUD/защита файлов.
- Docker собирается в несколько стадий: frontend, Composer, PHP production/dev-test, nginx. Только nginx публикует порт на loopback; БД и брокер остаются внутри сети Compose. Файлы хранятся в приватном volume.

## API

Полное описание: [OpenAPI](docs/openapi.yaml).

| Операция | Адрес |
|---|---|
| Проверка БД | `GET /api/health` |
| Сессия и CSRF | `GET /api/auth/session` |
| Вход / выход | `POST /api/auth/login`, `POST /api/auth/logout` |
| Список | `GET /api/products?page=1&limit=20&name=&min_price=&max_price=` |
| Карточка | `GET /api/products/{id}` |
| Экспорт всего каталога | `GET /api/products/export` |
| Загрузка | `POST /api/imports`, multipart-поле `file` |
| Прогресс / отчёт | `GET /api/imports/{id}` |
| Приватное изображение | `GET /api/images/{filename}` |

Кроме health/session/login требуется сессия. Все POST, включая login, требуют `X-CSRF-Token` из ответа session. Ошибки имеют один формат: `{"error":{"code":"validation","message":"…"}}`. Для XLSX и изображений возвращаются бинарные ответы. Цены/скидка в JSON — десятичные строки.

Поиск по названию не учитывает регистр русских и латинских букв. Каждое введённое слово ищется отдельно, в любом месте названия; порядок слов не важен. Например, `бермуды omsa`, `БЕРМУДЫ OMSA` и `omsa бермуды` находят «Бермуды мужские, … OMSA …». Повторные слова и лишние пробелы не влияют на результат; `%` и `_` воспринимаются как обычные символы. Поиск объединяется с диапазоном цен и серверной пагинацией.

## Правила импорта

Обязательны заголовки `Внешний код`, `Наименование`, `Цена: Цена продажи`, `Закупочная цена`. `Описание` опционально. Порядок колонок не влияет на сопоставление. Один непустой лист, первая строка — заголовки; несколько непустых листов и дубли заголовков отклоняются. Формулы не вычисляются и запрещены в импортируемых полях. Обычные колонки вне модели ТЗ игнорируются, поэтому экспорт сохраняет модель задания, а не все 50 исходных колонок.

Ключ идентификации — **Внешний код**. Он хранится текстом; текстовые ведущие нули и числовые маски с нулями сохраняются. Нельзя восстановить нули, если Excel уже удалил их и не сохранил числовой формат. Числовые коды с риском потери точности отклоняются. Цены принимают числовые ячейки или текст с точкой/запятой, максимум два десятичных знака. Продажная цена > 0, закупочная ≥ 0. Денежные вычисления используют BCMath.

`discount = (price − purchase_price) / price × 100`, четыре знака после точки, усечение без округления. Закупочная цена хранится отдельно ради сохранности при экспорте. Если она превышает продажную, скидка отрицательная — это следует формуле ТЗ. БД: цена/закупка DECIMAL(14,2), скидка DECIMAL(16,4).

Колонки с префиксом `Доп. поле` становятся атрибутами; префикс/двоеточие удаляются из ключа. Значения остаются строками, включая `0`; пустые/состоящие из пробелов значения не создают атрибут. Непустые значения и описание сохраняют исходные пробелы. Фото читаются из `Доп. поле: Ссылка на упаковку` и `Доп. поле: Ссылки на фото`, разделитель — запятая. Эти значения также остаются атрибутами для точного восстановления исходных URL.

При успешной строке товар и все его связи заменяются атомарно. Поэтому пустое поле удаляет старый атрибут. Повторный код внутри одного файла обновляется последней успешной строкой. Ошибка строки, цены или изображения пропускает **всю строку**, сохраняет прежнее состояние товара и добавляет лист/номер/причину в отчёт; остальные строки продолжают импортироваться.

Загрузка HTTP только сохраняет файл и задание, возвращает 202. Consumer Messenger выполняет импорт через RabbitMQ. Сохранённые задания служат outbox: отдельный dispatcher повторяет публикацию при недоступном брокере. Доставка может повториться; завершённая задача повторно не выполняется, а запись строки и её прогресса фиксируется одной транзакцией. Общая блокировка в shared storage сериализует consumers. Ошибки БД повторяются до трёх раз; затем задача отмечается failed, сообщение уходит в failure queue. Встроенные ошибки строк не требуют повторной доставки.

Изображения скачиваются до короткой транзакции БД. Новые файлы удаляются при откате, старые — после commit, если больше не используются. Общие URL кэшируются на время задачи; кэш очищается при удалении пути. После аварийного завершения процесса возможны непривязанные приватные файлы: они не отдаются API, но для долгой эксплуатации потребуется их периодическая уборка.

## Экспорт и ограничения

Порядок: `Внешний код`, `Наименование`, `Описание`, `Цена: Цена продажи`, `Закупочная цена`, `Скидка`, затем отсортированные `Доп. поле: …`. Текст задаётся явно строковым типом, поэтому строки с `=` не превращаются в Excel-формулы. Цены числовые. При повторном импорте скидка рассчитывается заново, связи заменяются; пустые значения и оригинальные URL сохраняются по описанным правилам. Пустые колонки, не имеющие ни одного значения в каталоге, в экспорт не включаются.

Ограничения защищают процесс с памятью 512 MiB:

- файл до 10 MiB; ZIP до 2 048 элементов и 50 MiB распакованных данных; XML до 20 MiB;
- до 10 000 товарных строк, 200 колонок, **100 000 фактических ячеек**, включая остальные листы; до 1 000 000 XML-узлов/атрибутов, 4 096 записей стилей, 100 000 shared strings и rich-text runs;
- для возможности обратного импорта всего экспорта: до 194 различных ключей дополнительных полей в каталоге, `(товары + строка заголовков) × (6 + ключи) ≤ 100 000`, консервативный общий бюджет текста 2 MiB с резервом на числовые значения/заголовки; превышение отклоняет строку до изменений;
- код/название/ключ до 255 символов, описание/значение до 10 000 символов;
- до 10 изображений на товар, 5 MiB на изображение, 25 MP, общий сетевой срок 10 секунд включая DNS (DNS до 3 секунд);
- импорт: до 5 запросов в минуту на пользователя; login: до 10 попыток за 5 минут на IP;
- server pagination: limit 1–100; поиск по названию и включительные границы цен.

Повреждённые архивы, повторяющиеся ZIP-имена, traversal, DTD/entities, шифрование, embedded drawings, объединённые ячейки и опасные внешние relationships отклоняются. Встроенные hyperlink relationships допустимы; загрузчик не обращается к ним автоматически.

## Безопасность и перерисовки

SQL параметризован, external_code уникален, атрибуты/изображения имеют FK с cascade deletion. Cookie HttpOnly/SameSite, смена session ID при входе, 30 минут бездействия, проверка Origin и CSRF. Статус задания доступен его владельцу. В production HTTPS выставьте SESSION_SECURE=1 и правильный APP_ORIGIN; TLS должен завершаться на доверенном reverse proxy. Пароли хешируются; пользователь создаётся из окружения. Регистрация и дополнительные роли не добавлены.

Скачивание разрешает только публичные HTTP(S)-адреса/порты, проверяет все A/AAAA, закрепляет проверенный IP в curl, отключает proxy и redirects. Содержимое проверяется Fileinfo и GD, размер/разрешение ограничены, имена файлов случайные; каталог файлов не является публичным webroot. Исходные metadata растров сохраняются. Все серверные подробности ошибок БД остаются в журнале.

Frontend использует OnPush, memoized selectors, async pipe, track по id. Фильтры debounce/distinctUntilChanged, Effects отменяет устаревший запрос через switchMap. Polling прекращается на completed/failed и при уходе со страницы; одинаковые статусы не вызывают повторных обновлений представления. Одновременно создаётся только одна разметка строк — desktop либо mobile. Повторная загрузка/экспорт блокируется во время операции.

## Проверки

```sh
make test           # PHPUnit; в Compose тесты используют отдельные PostgreSQL schemas
make analyse        # PHPStan level 6
make lint           # PHP CS Fixer dry-run
make frontend-test  # Angular unit tests в Docker
make e2e            # Playwright Chromium; запущенный чистый стенд Compose
```

E2E берёт данные входа из локальной .env, использует детерминированный `backend/tests/fixtures/e2e.xlsx` без внешних изображений и проверяет вход, CSRF, отчёт строки, каталог/фильтры, карточку, экспорт/повторный импорт, mobile layout, отсутствие browser errors и выход. Выполняйте его на отдельном проверочном каталоге: экспортирует весь каталог, а контрольные ожидания рассчитаны на эти две записи. HTTP-проверки без браузера: `cd tests && node api-smoke.mjs` (приложение должно быть запущено).

Без Docker доступны `cd frontend && npm ci && npm test && npm run build`. PHP требует перечисленные в composer.json расширения и `composer install`; штатный Messenger требует ext-amqp и RabbitMQ. Angular dev proxy направляет `/api` на localhost:8080; задайте backend `APP_ORIGIN=http://127.0.0.1:4200`, если запускаете frontend на этом адресе. Изменения окружения требуют перезапуска PHP.

SQLite и `tests/local-init.php` / `local-worker.php` используются только в изолированном нативном проверочном стенде, когда Docker недоступен. Это не подтверждает PostgreSQL/RabbitMQ-интеграцию и не заменяет штатный запуск Compose.

Результаты проверок и известные ограничения: [verification.md](docs/verification.md).

## Подготовка репозитория

Исходники и lock-файлы включены; .env, vendor, node_modules, сборки, логи, БД и загруженные изображения исключены. По условиям задания GitHub/GitLab репозиторий должен быть приватным во время разработки и публичным к сдаче. На GitHub доступна CI-конфигурация проверки push/PR.

```sh
git remote add origin <URL приватного репозитория>
git push -u origin main
```

## Ключевые решения архитектуры

Контроллеры Slim проверяют HTTP и вызывают сервисы. ExcelReader сопоставляет заголовки и готовит типизированные данные. Messenger worker обрабатывает сохранённое задание, скачивает изображения с защитой от SSRF и фиксирует товар, атрибуты, изображения и прогресс в одной короткой транзакции. Уникальный внешний код и сохранённый прогресс защищают от дубликатов при повторном импорте и доставке сообщения.

Angular получает постраничные данные через сервисы и NgRx. OnPush и отмена устаревших запросов уменьшают лишнюю работу интерфейса. Экспорт восстанавливает данные модели для обратного импорта.

Выбор версий сверялся с [совместимостью Angular](https://angular.dev/reference/versions), [релизами RabbitMQ](https://www.rabbitmq.com/release-information) и [документацией PhpSpreadsheet по чтению](https://phpspreadsheet.readthedocs.io/en/stable/topics/reading-files/).
